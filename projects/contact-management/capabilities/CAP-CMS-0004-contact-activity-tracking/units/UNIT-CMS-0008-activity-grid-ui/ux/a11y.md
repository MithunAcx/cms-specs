# Accessibility — Activity Grid UI

**WCAG target:** 2.2 AA

## Keyboard map

| Key | Context | Action |
|-----|---------|--------|
| Tab / Shift+Tab | Anywhere in the component | Moves through: sort control → filter control → (Editor only) add control → each row's cells in reading order → (Editor only) that row's edit/complete/delete controls → next row → load-more control (when present) |
| Enter / Space | Any button (add, edit, complete, delete, retry, clear filter, confirm/cancel, load more) | Activates it |
| Enter / Space | A sort-column header | Toggles that column's sort direction |
| Esc | Activity Editor dialog open (add or edit) | Closes the dialog without submitting; focus returns to the control that opened it |
| Esc | Delete-confirm dialog open | Cancels the delete; focus returns to that row's delete control |
| Arrow keys | Anywhere | No special behaviour — default browser scrolling (there is no composite pagination widget; the load-more control is a single button, not a set) |

## Focus order

1. Sort control
2. Completed/open filter control
3. Add control (Editor only)
4. Grid rows, top to bottom, each row's cells left to right, then that row's
   action controls (Editor only)
5. Load-more control (present only while `next_cursor` is non-null)

**On mount:** focus is left with the host screen (this component does not steal
focus on load) unless the host screen's own flow explicitly moves focus into it.

**On open** (add form, edit form, delete-confirm dialog): focus moves to the
dialog/form's first field (add/edit) or its confirm button (delete-confirm).

**On close** (Esc, cancel, or successful submit): focus returns to the control
that opened it — the add control, that row's edit control, or that row's delete
control.

**After submit (success):** focus moves to the success confirmation associated
with that row, so a screen-reader user both hears the outcome and lands somewhere
meaningful — not left on a control that has just disappeared (e.g. a deleted row's
own delete button).

**After an error:** focus moves to the error's own container — the field-level
error message (validation), the row-not-found message (404), the error block
(dependency-down/offline), or the session-expired banner (401) — never left on a
control that may no longer be valid to act on.

**After every terminal outcome** (row removed as no-longer-available, session
expired): focus moves to the nearest still-valid control — the grid's own
container for a removed row, or the session-expired banner's own re-authenticate
guidance for a `401` — never left dangling on a now-removed element.

## Semantics

| Element | Role | Accessible name | Notes |
|---|---|---|---|
| Grid | `table` (real table markup, not a styled div) | "Activity for {parent name}" | Column headers use `<th scope="col">` |
| Sort-column header | `columnheader` with `aria-sort` | "Follow-up date, sortable" | `aria-sort` reflects current direction |
| Completed/open filter | `group` of toggle/radio-like controls, or a `select` | "Filter by status" | Current selection is programmatically exposed, not colour-only |
| Load-more control | `button` | "Load more activity" | Rendered only while `next_cursor` is non-null; disabled for the duration of its own in-flight request (R14) |
| Add control | `button` | "Log activity" | Rendered only for Editor; absent, not `aria-disabled`, for Viewer (R12/R28) |
| Row edit control | `button` | "Edit activity from {entered date}" | Name disambiguates rows sharing a task type |
| Row complete control | `button` | "Mark complete: activity from {entered date}" | — |
| Row delete control | `button` | "Delete activity from {entered date}" | Opens the confirm dialog, does not delete directly |
| Activity Editor dialog | `dialog` | "Log activity" (add mode) / "Edit activity from {entered date}" (edit mode) | Modal; background inert while open; carries no completed/completion-date control (R7) |
| Delete-confirm dialog | `alertdialog` | "Delete this activity entry?" | Modal; background inert while open |
| Error block | `region` with `aria-live="assertive"` on mount of the error | "Activity could not be loaded" | Contains the retry button |
| Session-expired banner | `region` with `aria-live="assertive"` | "Your session has ended" | Not dismissible without re-authenticating |
| Field-level validation message | Associated via `aria-describedby` on the field | (read as part of the field's description) | Announced when it appears, not only on next focus |

## Announcements

| Event | Live region | Politeness | Text |
|---|---|---|---|
| Initial load fails (dependency down, offline) | Error block | assertive | "Activity could not be loaded." |
| Rate-limited (`429`) | Inline near the triggering control | polite | "Too many requests — try again in {n}s." |
| Add/edit succeeds | Row-scoped confirmation | polite | "Changes saved." / "Activity logged." |
| Mark-complete succeeds | Row-scoped confirmation | polite | "Marked complete." |
| Delete succeeds | Grid-scoped confirmation (the row itself is gone) | polite | "Entry removed." |
| Row 404s on edit/complete/delete | Row area, before removal | assertive | "This entry is no longer available." |
| Session expires (`401`) | Session-expired banner | assertive | "Your session has ended. Sign in again to continue — your entry has been kept." |
| Filter/sort changes and reloads the grid | Not announced as a live region — the grid's own updated content and the moved focus (none moves) are sufficient; over-announcing routine list changes is noise | — | — |
| Load-more succeeds | Not a separate live region — the newly appended rows are part of the same `table`, discoverable by continuing to navigate; over-announcing routine pagination is noise | — | — |

## Visual

| Requirement | Target |
|---|---|
| contrast — text | ≥ 4.5:1 |
| contrast — UI/graphics | ≥ 3:1 |
| target size | ≥ 24×24 CSS px |
| zoom | usable at 200% |
| motion | respects reduced-motion (no animation is used anywhere in this component) |
| colour | never the sole carrier of meaning — every disabled, error, and success state also carries text, not colour alone |

## Not covered

- Voice-control software-specific labelling (e.g. Voice Control/Dragon numbered
  overlays) — not requested, and no unit in this project has specified it yet.
- Right-to-left layout — the project's locale set (en, de, fr per `60-frontend.md`)
  is all left-to-right; RTL was not asked for and is not designed here.
