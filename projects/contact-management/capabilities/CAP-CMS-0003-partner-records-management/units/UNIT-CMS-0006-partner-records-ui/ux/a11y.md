# Accessibility — Partner Records UI

**WCAG target:** 2.2 AA

## Keyboard map

| Key | Context | Action |
|-----|---------|--------|
| Tab / Shift+Tab | Any screen | Move focus forward/backward through interactive elements in visual order |
| Enter | A focused button, or a focused inline-grid row's Edit control | Activate it |
| Space | A focused button, checkbox (e.g. history/disabled flag), or tab | Activate/toggle it |
| Esc | Accounting-address dialog, two-choice confirmation dialog, an open address-suggest suggestion list, an inline-grid row in edit mode | Close the dialog/list without saving; for a grid row, revert that row's edits and return it to read-only |
| Arrow Up / Down | Address-suggest suggestion list; the reference-lookup admin list when focus is on a list item | Move the highlighted suggestion/item; does not move page focus |
| Enter (in suggestion list) | A highlighted address suggestion | Accept it, filling the address fields (R2/R14/R22) |
| Tab within a dialog | Accounting-address dialog, two-choice confirmation dialog | Focus is trapped inside the dialog until it closes |

## Focus order

1. App header (not focusable, landmark only)
2. Tab bar / breadcrumb-back control, where present
3. Screen title
4. Master-details fields in reading order (name → address block → phone/fax → tax id → underwriter → status → contract-received date → history flag), or the grid's first interactive control on grid-first screens (CGA)
5. Grid/embedded-panel region (Brokers/Agents/CGA grid, then activity panel, then policy panel)
6. Save / Cancel (or Back) controls, last

**Focus on route entry:** the screen title (`.text-h2`/`.text-h1`) receives focus so a screen-reader user hears what changed.

**Focus on dialog open:** the dialog's own heading receives focus (Accounting-address dialog, two-choice confirmation dialog).

**Focus on dialog close:** focus returns to the control that opened the dialog (e.g. the "Accounting address" button on Brokerage Detail).

**Focus after submit (success):** focus moves to the inline confirmation message, so its text is the next thing announced; on the two-choice dialog it moves to the dialog heading.

**Focus after error:** focus moves to the error block itself (conflict, validation summary, unresolved, rate-limited, or terminal not-found message) — never left on the now-disabled Save button. For a per-field `400`, focus moves to the first invalid field.

**Focus after every terminal outcome:** on a `404` full-screen terminal state, focus moves to the terminal message heading, and the only remaining interactive control (Return to Directory) is the next tab stop.

## Semantics

| Element | Role | Accessible name | Notes |
|---|---|---|---|
| Master-details field group | `group` | "Brokerage details" / "Agency details" | Groups related fields for screen-reader navigation |
| Brokers/Agents/CGA grid | `table` (real `<table>` per design-system §5) | "Brokers", "Agents", "CGA records" | Header row uses `<th scope="col">` |
| Inline grid row edit control | `button` | "Edit broker <first> <last>" (name interpolated, never "Edit" alone) | Accessible name always includes the row's identifying value |
| Status badge | `img`-like text span, `aria-hidden` on the shape-mark character, label read normally | the status label text ("In force", "Pending", etc.) | The shape-mark glyph itself is decorative; the adjacent text carries the name |
| Accounting-address dialog | `dialog` (`role="dialog"`, `aria-modal="true"`) | "Accounting address" | Labelled by its own heading via `aria-labelledby` |
| Two-choice confirmation dialog | `dialog` (`role="dialog"`, `aria-modal="true"`) | "Agency created" | Labelled by its own heading |
| Address-suggest suggestion list | `listbox` | "Address suggestions" | Options are `option` role; selection via Enter or click |
| Conflict / error block | `alert` (`role="alert"`) | (the block's own heading text) | Announced immediately on appearance |
| Disabled Save button | `button`, `aria-disabled="true"` during submission | "Save" | Caption text below states why it is disabled during submission ("Saving…") |
| History / disabled flag control | `checkbox` | "Mark as history" / "Mark as disabled" | Never conveyed by colour or icon alone |
| Load more (Brokers/Agents grid) | `button` | "Load more brokers" / "Load more agents" | Present only while `next_cursor` is non-null; absent (not disabled) once the last page has loaded, per 10-platform.md's cursor-only rule |

## Announcements

| Event | Live region | Politeness | Text |
|---|---|---|---|
| Save succeeded | `status` (moves focus to it per Focus after submit) | polite | "Saved." |
| Save rejected — conflict (`409`) | `alert` | assertive | conflict.title + conflict.body (copy table) |
| Save rejected — validation (`400`) | `alert` | assertive | Field-specific messages; summary at top names the count ("2 fields need attention") |
| Save rejected — not permitted (`403`) | `alert` | assertive | notPermitted.title + notPermitted.body |
| Save unresolved (timeout/offline) | `alert` | assertive | unresolved.title + unresolved.body |
| Rate limited (`429`) | `alert` | assertive | rateLimited.title + rateLimited.body |
| Screen load failed | `alert` | assertive | unableToLoad.title + unableToLoad.body |
| Embedded panel (activity/policy) failed independently | `status`, scoped to that panel only | polite | "This panel couldn't load. Retry." |
| Address suggestion accepted | `status` | polite | "Address filled." |
| Session expired mid-flow | `alert` | assertive | sessionExpired.title + sessionExpired.body |
| Reconnected after offline | `status` | polite | "Back online." |
| Further page of Brokers/Agents loaded | `status`, scoped to that grid | polite | "N more rows loaded." (N interpolated) |

## Visual

| Requirement | Target |
|---|---|
| contrast — text | ≥ 4.5:1 |
| contrast — UI/graphics | ≥ 3:1 |
| target size | ≥ 24×24 CSS px |
| zoom | usable at 200% |
| motion | respects reduced-motion (no animation is used anywhere in this unit's screens per design-system §8) |
| colour | never the sole carrier of meaning — status badges always pair a shape-mark character and a text label with colour (design-system §7); disabled controls always carry caption text explaining why |

## Not covered

- Voice-control naming conventions beyond the accessible-name rules above — not requested by any requirement, and no capability outcome depends on it.
- Locale-specific screen-reader behaviour differences (en/de/fr voice engines) — `60-frontend.md`'s locale requirement is about text expansion and layout holding, which the layout section covers; per-locale screen-reader tuning is out of scope for this spec.
