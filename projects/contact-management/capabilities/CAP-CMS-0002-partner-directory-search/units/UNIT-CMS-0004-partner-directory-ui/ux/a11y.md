# Accessibility — Partner Directory UI

**WCAG target:** 2.2 AA

## Keyboard map

| Key | Context | Action |
|-----|---------|--------|
| Tab / Shift+Tab | Whole screen | Moves through: mode switcher options, term/state input, search submit, Assigned Underwriter filter, results (row by row), Add New Agency/Brokerage, pagination controls, in that order |
| Enter / Space | Mode switcher option focused | Selects that mode, clears the previous mode's term/state (R2) |
| Enter | Term/state input focused | Submits the search (same as activating the Search button) |
| Enter / Space | Result row focused | Opens that row's detail screen (R10) |
| Enter / Space | Retry button focused (error — recoverable) | Re-issues the same search |
| Arrow Left / Right | Mode switcher (segmented control) focused | Moves focus between mode options without selecting; Enter/Space selects the focused option |
| Arrow Down / Up | Assigned Underwriter dropdown open | Moves through the option list |
| Esc | Assigned Underwriter dropdown open | Closes the dropdown without changing the selection |

## Focus order

1. Skip-to-results link (if the app shell provides one)
2. Mode switcher (segmented control, roving tabindex across its options)
3. Term or state input, whichever the current mode requires
4. Search submit button
5. Assigned Underwriter filter
6. Results region (table rows, or cards, in display order)
7. Pagination controls
8. Add New Agency / Add New Brokerage (when present, per role)

**On route entry:** focus moves to the mode switcher's first option (or the
previously-selected mode, if the screen is re-entered with prior state after
session-expiry recovery).

**On close:** not applicable — this is a landing screen with no dismissible
overlay of its own; the Assigned Underwriter dropdown returns focus to the filter
control itself on close (Esc or selection).

**After submit (search issued):** focus does not move away from the search
controls while loading; once results resolve, focus moves to the results region's
heading (the result-count line) so a screen-reader user is told the outcome and is
positioned at the content that follows it, rather than a live region alone.

**After an error:** focus moves to the error block's heading (Retry-recoverable or
terminal), so the user is not left on a control that no longer describes what
happened.

**After every terminal outcome:** the terminal-error frame moves focus to its own
heading, same as above — there is no further action inside this screen after that
point besides changing search inputs.

## Semantics

| Element | Role | Accessible name | Notes |
|---|---|---|---|
| Mode switcher | `radiogroup` / `radio` per option | "Search mode" (group), each option's label ("By Brokerage", etc.) | Selected state exposed via `aria-checked`, not colour alone (design-system.md §7's rule extends to this control: the active mode also carries the 2px underline treatment) |
| Term/state input | `textbox` (term) or `combobox`/`listbox` (state) | "Search term" / "State" | Associated `aria-describedby` to the validation message when present |
| Assigned Underwriter filter | `combobox` | "Assigned Underwriter" | `aria-expanded`, `aria-activedescendant` on the open listbox |
| Results table | `table` with `columnheader`s | Table itself named "Search results" | Row `role="row"`, cells plain `td`/`th` — a real `<table>` per design-system.md §5 |
| Results cards (mobile) | `list` / `listitem` | "Search results" | Each card's accessible name is its primary field (e.g. brokerage name) |
| Status badge | `img`-like text span, `aria-hidden` on the glyph, visible text label read normally | n/a — the text label ("Active"/"Disabled") is the accessible name | Shape-mark glyph is decorative once the text label is present |
| Add New Agency / Add New Brokerage | `link` or `button` (navigation) | "Add New Agency" / "Add New Brokerage" | Absent from the accessibility tree entirely when role-gated (R18) — not `aria-disabled` |
| Error block heading | `heading`, level appropriate to context | Matches the error title copy | Focus target after an error (see Focus order) |
| Empty-state block | `status` region or plain text with a heading | "No records to display" | Not a live region on initial render — only announced if it replaces a prior populated state (see Announcements) |

## Announcements

| Event | Live region | Politeness | Text |
|---|---|---|---|
| Search resolves (populated or empty) | `aria-live` region tied to the result-count line | polite | "{count} results" or "No records to display" |
| Search fails (recoverable) | `aria-live` region tied to the error heading | assertive | "We couldn't load results. {retry instruction}" |
| Search fails (terminal) | Same region | assertive | "Search is unavailable. Contact support if it continues." |
| Rate-limited | Same region | assertive | "Too many searches. Please wait a moment before searching again." |
| Session expired mid-flow | Page-level announcement before redirect | assertive | "Your session expired. Sign in again to continue." |
| Assigned-UW lookup fails (partial) | `aria-live` region local to the filter | polite | "Underwriters unavailable right now — mode search still works." |

Per `60-frontend.md`'s preference, every one of these also moves focus to the
corresponding heading (see Focus order) rather than relying on the live region
alone — the region announces the change for a user who is not currently focused
there (e.g. was still typing), and the focus move handles the case where they are.

## Visual

| Requirement | Target |
|---|---|
| contrast — text | ≥ 4.5:1 |
| contrast — UI/graphics | ≥ 3:1 |
| target size | ≥ 24×24 CSS px |
| zoom | usable at 200% |
| motion | respects reduced-motion (no animated skeleton shimmer — a static skeleton bar, per design-system.md §5) |
| colour | never the sole carrier of meaning — status badges carry a shape-mark glyph and a text label; the selected mode carries an underline rule, not colour alone |

## Not covered

- Voice control and switch-access device testing — out of scope for this spec; flagged for the engineering repo's own QA pass, since this repo specifies behaviour, not a test plan.
- Right-to-left layout — not required; en/de/fr are all LTR locales (60-frontend.md's locale list).
